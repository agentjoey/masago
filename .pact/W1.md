## 交付物

### 1. 工程基线

`package.json`：
- `"type": "module"`，`"packageManager": "pnpm@10.33.0"`
- scripts：`dev`、`build`、`typecheck`、`lint`、`test`、`test:watch`
- 依赖仅限：`zod`、`pino`
- devDependencies 仅限：`typescript`、`vitest`、`@types/node`、`eslint`、`typescript-eslint`、`pino-pretty`
- **不要**引入任何其他依赖。需要别的，在交付说明里提出。

`tsconfig.json`：`strict: true`、`module: nodenext`、`moduleResolution: nodenext`、`target: es2023`、`noUncheckedIndexedAccess: true`、`outDir: dist`、`rootDir: .`。

`eslint.config.js`：flat config，接入 typescript-eslint recommended，额外开启禁止 `any`（`@typescript-eslint/no-explicit-any: error`）与禁止 `console`（`no-console: error`）。

`.gitignore`：至少含 `node_modules`、`dist`、`.env`、`.env.*`（但保留 `!.env.example`）、`*.log`、`.DS_Store`。

### 2. `src/config/`

按 `docs/architecture.md` §17 的**完整**配置清单写一个 Zod schema。要点：

- 分组导出为嵌套结构（`config.telegram.botToken`、`config.db.poolMax`、`config.stt.model` …），不要一个 60 项的扁平对象。
- 数值类型（如 `DB_POOL_MAX`）用 `z.coerce.number()`，布尔（如 `STT_CONTEXT_HINTS_ENABLED`）用能正确处理 `"false"` 字符串的方式——**注意 `Boolean("false") === true` 这个坑**。
- 默认值写在 schema 里：`DB_POOL_MAX=2`、`DB_POOL_IDLE_TIMEOUT_MS=15000`、`DB_CONNECTION_TIMEOUT_MS=10000`、`SESSION_IDLE_MINUTES=30`、`LLM_MAX_CONTEXT_TURNS=12`、`SURFACE_AFTER_TURNS_CONVERSATION=4`、`SURFACE_AFTER_TURNS_COACH=1`、`SURFACE_MAX_ITEMS=3`、`AUDIO_TARGET_CONTAINER=webm`、`TTS_MAX_CHARACTERS=400` 等。
- 校验失败时：收集**全部**错误后一次性打印字段名与原因，然后 `process.exit(1)`。**错误信息里不得出现变量的值。**
- 导出对象 `Object.freeze`。
- `USER_TIMEZONE` 校验为合法 IANA 时区（可用 `Intl.supportedValuesOf` 或 `Intl.DateTimeFormat` 试构造）。
- `DAILY_REMINDER_LOCAL_TIME` / `NIGHTLY_BACKUP_LOCAL_TIME` 校验为 `HH:MM` 24 小时格式。

`.env.example` 列全所有变量，密钥类留空，非密钥给出合理默认。

### 3. `src/observability/`

按 `INTERFACES.md` §3 实现。要点：

- `redact.ts`：导出 `redact(value: unknown): unknown`。
  - 字段名匹配 `/token|key|secret|password|authorization|connection_string|database_url/i` 的**值**替换为 `"<redacted>"`。
  - **必须递归**处理嵌套对象与数组。
  - 必须处理循环引用（不能栈溢出）。
  - 字符串字段超过 200 字符时截断并加 `…(truncated)` 后缀。
- `logger.ts`：基于 pino 封装出 `INTERFACES.md` §3 的 `Logger` 接口。所有 `fields` 在传给 pino 前先过 `redact`。生产输出 JSON，开发用 pino-pretty。日志级别取自 `LOG_LEVEL`。
- `correlation.ts`：用 `node:async_hooks` 的 `AsyncLocalStorage` 实现 `withCorrelationId`，并让 `logger` 自动带上当前 correlation ID。
- `index.ts` 统一导出。

### 4. `src/app.ts`

最小启动骨架：加载 config → 初始化 logger → 打印一条启动日志（含版本，不含任何密钥）→ 注册 `SIGINT`/`SIGTERM` 优雅退出钩子。**暂不启动 bot、不连数据库**（那是 W2/W3）。

### 5. 测试

用 vitest，至少覆盖：

- config 缺少必需变量时 fail fast，且错误信息包含**所有**缺失字段名
- config 错误信息**不包含**变量的值（用一个含敏感值的非法配置断言）
- `DB_POOL_MAX` 等数值默认值正确生效
- 布尔变量 `"false"` 被正确解析为 `false`（这是最容易写错的一条，必须有测试）
- 非法 `USER_TIMEZONE` 与非法 `HH:MM` 被拒绝
- `redact` 对**嵌套对象**中的 `apiKey` / `DATABASE_URL` 生效
- `redact` 对循环引用不崩溃
- `redact` 对超长字符串截断
- `withCorrelationId` 内产生的日志带有该 ID

测试不得依赖真实环境变量；用注入的方式构造配置输入。
