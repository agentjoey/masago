## 1. 接入 MiniMax（基础改造）

### 1.1 配置

`src/config/schema.ts` 增加 `LLM_BASE_URL`（可选，有默认值）：

```
LLM_PROVIDER=minimax
LLM_BASE_URL=https://api.minimax.io/anthropic
LLM_MODEL=MiniMax-M3
```

`.env` 已由 orchestrator 更新为上述值（`LLM_BASE_URL` 待你加进 schema 后生效）。

### 1.2 客户端

`@anthropic-ai/sdk` 的 `baseURL` 指向 `config.llm.baseUrl`。**SDK 与调用结构基本不动**——这正是 §6.2 Provider Adapter 的设计目的。

### 1.3 输出方式：`output_config.format` → 强制工具调用

```ts
tools: [{ name: 'submit_tutor_turn', description: '...', input_schema: TUTOR_INPUT_SCHEMA }],
tool_choice: { type: 'tool', name: 'submit_tutor_turn' },
```

从 `content` 里取 `type === 'tool_use'` 的块，`tool_use.input` 即结构化结果，仍用 Zod 校验。

**注意：** 响应里可能**同时**有 `text` 块和 `tool_use` 块（探针实测出现过）。取值必须找 `tool_use`，不能假设 `content[0]`。

### 1.4 参数

不传 `temperature` / `top_p` / `top_k`。现有实现已如此，无需改动——这个写法对 MiniMax 与 Anthropic 原生都合法。`top_k` 与 `stop_sequences` 在 MiniMax 端点被静默忽略，不要依赖它们。

## 2. 问题一：`knowledgeKey` 必须是稳定键（必修）

**探针实测**：模型返回的 `knowledgeKey` 是 `"動詞の過去形：見る → 見ました"` 这样的自由文本描述。

**为什么致命**：§3.3 的 mastery 是**按知识项聚合 learning events** 算出来的。同一类错误每次生成不同的 key，掌握度永远累积不起来，Error Bank 会碎成一堆各出现一次的孤立条目——看起来有数据，实际上完全无法用于复习调度。

**修法**（不要用硬枚举，会挡住合理的新错误类型）：

1. schema 中约束 `knowledgeKey` 为 `^[a-z][a-z0-9_]*$` 的 snake_case 标识符
2. 调用时把**当前已知的 key 列表**放进上下文，指示模型：能匹配已有 key 时必须复用，确无匹配才新造
3. 程序侧把新出现的 key 注册进 `knowledge_items`（表已存在，`(type, key)` 有唯一约束，天然幂等）

初始键空间覆盖 N5 常见错误类型即可，例如 `verb_masu_past`、`particle_ni_de`、`adjective_i_negative`、`counter_usage`。**不要试图一次穷举**——机制对了，键空间会随使用自然生长。

**必须有测试**：断言自由文本形式的 key（含空格、日文、箭头）被 Zod 拒绝。

## 3. 问题二：HOLD 不泄漏需用真模型验证（必修）

**探针实测**：M3 的默认倾向是**在 `reply.japanese` 正文里直接纠错**。第 1 例的回复是「自然な日本語に直すと、『昨日、友達と映画を見ました。』になります…」——纠正写进了正文。

探针没发 HOLD 指令，所以这是预期行为。但它说明：

- W9 的程序级防护只强制清空 `correctionCard`，**管不到 `reply.japanese` 的正文泄漏**
- W9 那条「HOLD 时正文不含推荐表达」的断言是对**打桩 client** 做的，从未跑过真模型
- 换模型后这条保证的实际有效性是**未知的**

**要做的：**

1. 在 TUTOR_POLICY 的指令协议里强化 HOLD 措辞（模型默认倾向强，需要更明确的禁止）
2. 新增**离线**测试：打桩 client 返回夹带纠正的 reply，断言程序侧行为符合预期
3. 新增**在线**验证脚本 `scripts/verify-llm.ts`，用真实 API 验证 HOLD 不泄漏

### 关于在线验证的边界（重要）

- **单元测试与 CI 必须保持离线**，绝不发真实 API 调用。CI 无密钥，且不该为验证烧钱。
- 在线验证是**独立脚本**，通过 `pnpm verify:llm` 手动运行，不进 `pnpm test`。
- 脚本需连续多次（≥5）用含明显错误的输入 + HOLD 指令调用，断言 `reply.japanese` 不含推荐表达，并报告通过率。
- **如实报告结果**。若真模型下泄漏率不为零，在交付说明里明说——这是真实的产品风险，掩盖它比暴露它糟得多。届时由 orchestrator 决定是加程序级后处理还是调整策略。
