## 1. 连接层 `src/db/client.ts`

**这是 architecture.md R1 的落地点，不是可以"顺手优化"的地方。**

- 用 `pg` 的 `Pool` + Drizzle `node-postgres` adapter，**不要用 `neon-http`**。
- 池参数全部来自 `config.db`：`max`、`idleTimeoutMillis`、`connectionTimeoutMillis`。
- 导出 `db` 与 `closeDb()`。
- **严禁**：定时 ping、keep-alive、连接预热、`setInterval` 健康探测、任何形式的固定频率查询。
- 数据库空闲时连接必须真正断开。任何"让连接保持活跃"的代码都是 bug。
- 连接错误日志**不得**打印连接串（logger 已有脱敏，但不要主动把它塞进 message 字符串）。

**SSL 注意（Neon + node-postgres 的经典坑）：** `.env` 里的连接串带 `?sslmode=require`，但 `pg` 对 URL 中 `sslmode` 的解析在不同版本行为不一致，常见症状是 `self signed certificate in certificate chain` 或 SSL 直接未启用。请**实际连一次真库验证**，必要时在 Pool 配置里显式给 `ssl` 选项。不要想当然认为连接串里写了就生效——先跑通再说。

**数据库当前是空的**（orchestrator 已验证连通，`neondb` 无任何表），你可以放心跑迁移。

## 2. Schema `src/db/schema/`

按 `docs/architecture.md` §7.2 建 **12 张表**。按领域分文件（如 `learner.ts`、`session.ts`、`knowledge.ts`、`ops.ts`），在 `src/db/schema/index.ts` 统一导出。

### 表清单与必须存在的唯一约束

| 表 | 必须的唯一约束 |
|---|---|
| `learner_profiles` | `telegram_user_id` 唯一 |
| `sessions` | — |
| `turns` | `telegram_message_id` 唯一 |
| `detected_issues` | `(turn_id, knowledge_key, original)` 唯一 |
| `knowledge_items` | `(type, key)` 唯一 |
| `learning_events` | `dedupe_key` 唯一 |
| `review_queue` | `(learner_id, knowledge_item_id)` 唯一 |
| `daily_plans` | `(learner_id, plan_date)` 唯一 |
| `daily_plan_items` | — |
| `telegram_updates` | `update_id` 唯一 |
| `usage_records` | — |
| `outbox_jobs` | `dedupe_key` 唯一 |

**这些唯一约束是 §9.2 幂等策略的物理保证，一条都不能少。** 必须建在数据库层（unique index / unique constraint），不能只在应用层判重。

### 枚举（用 pgEnum）

```
session_mode      : CONVERSATION | COACH | CHALLENGE
session_status    : ACTIVE | CLOSED
turn_input_type   : TEXT | VOICE
turn_status       : RECEIVED | AUDIO_READY | AUDIO_NORMALIZED | STT_DONE
                  | LLM_DONE | PERSISTED | TEXT_SENT | VOICE_SENT | COMPLETED | FAILED
knowledge_type    : VOCABULARY | GRAMMAR | EXPRESSION | ERROR_PATTERN
learning_event_type : INTRODUCED | REVIEWED | USER_ERROR | USER_CORRECT | RETRY_SUCCEEDED
                    | FAILED_RECALL | USED_WITH_HINT | USED_SPONTANEOUSLY | MASTERED
importance        : LOW | MEDIUM | HIGH
retry_status      : NONE | REQUESTED | SUCCEEDED | FAILED
review_state      : NEW | LEARNING | REVIEW | MASTERED
plan_status       : DRAFT | ACTIVE | COMPLETED | ABANDONED
plan_item_type    : REVIEW | NEW | CHALLENGE
update_status     : RECEIVED | PROCESSING | PROCESSED | FAILED
job_status        : PENDING | RUNNING | DONE | FAILED
```

`turn_status` 的取值顺序必须与 `docs/architecture.md` §8.2 的状态机一致。

### 字段约定

- 主键统一 `uuid`，默认 `gen_random_uuid()`。
- 所有时间戳用 `timestamptz`，创建时间 `defaultNow()`。**不接受 `timestamp without time zone`。**
- `turns` 必须分别有 `raw_transcript` 与 `normalized_transcript` 两列（§6.3，raw 不可被覆盖）。
- `detected_issues` 必须有 `surfaced_at`（可空，NULL = 待呈现）与 `retry_status`。
- `usage_records` 必须有 `cached_input_tokens`（§12.3）与 `pricing_version`。
- `daily_plans` 必须有 `source_snapshot`（jsonb，用于复现生成依据）。
- 外键统一显式声明，删除行为按语义选择（学习事件不随 session 级联删除）。
- 需要按时间/状态查询的列建索引：`turns.session_id`、`review_queue.next_review_at`、`outbox_jobs.due_at + status`、`detected_issues.surfaced_at`、`learning_events.knowledge_item_id`。

## 4. Repositories `src/db/repositories/`

按 `INTERFACES.md` §4.2：纯函数、第一参数为 `Executor`（`db` 或事务）、不使用 class。

W2 只需实现后续任务立刻要用的最小集合：

- `telegramUpdates`：`insertIfAbsent(tx, updateId, payload)` → 返回 `{ inserted: boolean, record }`。**用数据库唯一约束实现幂等**（`onConflictDoNothing` + 返回值判断），不要先 SELECT 再 INSERT——那有竞态。
- `learnerProfiles`：`findByTelegramUserId`、`upsert`
- `sessions`：`findActiveByLearner`、`create`、`touch`（更新 last_activity_at）、`close`
- `turns`：`create`、`updateStatus`、`findByTelegramMessageId`

其余 repository 留到后续任务包，不要提前写。

## 5. 测试

**允许连真实 Neon dev 数据库**（`.env` 已由 orchestrator 配好 `DATABASE_URL` / `DATABASE_URL_DIRECT`）。若连不上，跳过集成测试并在交付说明里明说，不要伪造通过。

至少覆盖：

- 迁移可在空库上完整执行
- `telegramUpdates.insertIfAbsent` 对同一 `update_id` 调用两次：第一次 `inserted=true`，第二次 `inserted=false`，且表中只有一条记录
- `turns.telegram_message_id` 重复插入抛唯一约束错误
- `review_queue` 同一 `(learner_id, knowledge_item_id)` 重复插入被拒
- 时间戳写入后读回为 `timestamptz`
- 池配置确实取自 config（可断言 `pool.options.max === 2`）

测试后清理自己创建的数据。
