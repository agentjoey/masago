## 1. Bot 组装 `src/telegram/bot.ts`

按 `INTERFACES.md` §5 的 `createBot(deps)` 签名。使用 **Long Polling**，不使用 Webhook。

**middleware 顺序固定，不可调整：**

```
1. correlationId   为本次 update 生成 ID，绑定到 logger（用 W1 的 withCorrelationId）
2. auth            telegram_user_id !== config.telegram.allowedUserId → 立即静默返回
3. dedupe          update_id 已存在 → 立即返回
4. route           分发到 sessions/orchestrator
```

### 1.1 auth（§10.1，安全关键）

- 这是**第一道业务校验**，必须在任何外部调用与业务写入之前。
- 不匹配时：**静默返回**。不回复消息、不调用任何供应商 API、不返回含系统信息的错误。
- 记一条 `warn` 日志（含 user id，不含消息内容）用于观察，仅此而已。

### 1.2 dedupe（§9.2）

- 用 W2 的 `telegramUpdates.insertIfAbsent(db, updateId, payload)`。
- 返回 `inserted === false` 时立即返回，不进入业务处理。
- **依赖数据库唯一约束保证幂等**，不要先 SELECT 再 INSERT。
- 注意顺序：auth 在 dedupe 之前。未授权用户的 update **不应该**写进 `telegram_updates`，避免陌生人灌数据。

## 2. Session Orchestrator（最小实现）

`src/sessions/orchestrator.ts` 本任务只需：

- 收到文本消息 → 复用或创建 session（用 W2 的 `sessions` repository）→ 写入 `turns` 记录 → **原样 echo 回用户**，前缀 `echo: `。
- 语音消息 → 回复"语音功能尚未启用"（阶段 2 再实现），**不要**下载音频、不要调 STT。
- 超过 `SESSION_IDLE_MINUTES` 的旧 session 视为已关闭，创建新 session。**惰性判定**——只在有新消息进来时判断，**严禁**定时扫描（`docs/architecture.md` §4.2）。

这是纵向冒烟通路，不是真正的 Tutor。Tutor 行为属于阶段 3。

## 3. app.ts 接入

- 启动 bot（long polling），把 `bot.stop()` 与 W2 的 `closeDb()` 注册到 W1-fix 建立的 `onShutdown` 钩子。
- 移除 W1 里那个纯粹用于保活事件循环的 `setInterval` —— long polling 会自然保持进程存活，它已成冗余。
- 启动日志打印 bot username（可从 `bot.api.getMe()` 拿），**不得打印 token**。

## 5. CI `.github/workflows/ci.yml`

GitHub Actions，触发于 push 与 pull_request：

```
lint → typecheck → test → build
```

- 用 pnpm（`pnpm/action-setup`）与 Node 22。
- **不要**在 CI 里跑需要真实数据库的集成测试；用环境变量或 vitest 的 tag/项目区分，CI 只跑单元测试。
- CI 中**不得**引用任何真实密钥。需要 env 时用明显的假值。
- 迁移检查（`db:generate` 后确认无未提交的 schema 漂移）可以加，但若做不到就在交付说明里说明，不要伪造。

## 6. 测试

难点是 grammY 需要真实 Bot API。**不要真的联网。** 用直接构造 `Context` 或调用 middleware 函数的方式测试，必要时对 `bot.api` 打桩。

至少覆盖：

- **未授权 user id 的 update 不会触达下游 middleware**（用 spy 断言 route 未被调用），且**未产生任何外部调用**
- 未授权 update **不会**写入 `telegram_updates`
- 授权 user 的正常文本 update 走完全链路并触发 echo
- 同一 `update_id` 处理两次：第二次被 dedupe 拦截，`telegram_updates` 只有一条记录，且 echo 只发一次
- 超过 idle 阈值后创建新 session，未超过则复用
- 语音消息返回"未启用"提示且**不触发任何音频下载或 STT 调用**

数据库相关测试可连真实 Neon dev 库；连不上就跳过并在交付说明里明说。
