## 1. `src/speech/ffmpeg.ts` —— FFmpeg 调用层

- 导出 `isFfmpegAvailable(): Promise<boolean>`，通过 `ffmpeg -version` 探测，结果可缓存。
- 导出 `runFfmpeg(args: string[]): Promise<{ stdout, stderr }>`。
- **必须用 `spawn` 传数组参数，禁止拼接 shell 字符串。** 文件名虽由我们生成，但不给命令注入留任何面。
- 设超时（默认 30 秒），超时后 kill 子进程并抛出可识别的错误类型。
- 失败时把 ffmpeg 的 stderr 纳入错误信息，便于诊断——但注意 stderr 可能很长，按 logger 的截断规则处理。

## 2. `src/speech/normalizer.ts` —— 音频容器转换（§8.1 第 6 步）

这是 architecture.md **R3** 的落地点。背景：OpenAI 转写 API 官方支持 `mp3/mp4/mpeg/mpga/m4a/wav/webm`，**不含 ogg**，而 Telegram 语音条正是 OGG/Opus。

```ts
export interface NormalizedAudio {
  path: string;
  container: string;      // 'webm' | 'ogg' | ...
  codec: string;          // 'opus' | ...
  transcoded: boolean;    // 是否发生了重编码（应恒为 false）
  durationMs?: number;
}

export async function normalizeForStt(
  input: { path: string; container: string },
  supportedInputFormats: readonly string[],
): Promise<NormalizedAudio>;
```

**核心约束：**

- 若输入容器已在 `supportedInputFormats` 内 → **原样返回，不做任何处理**。
- 否则 OGG/Opus → WebM/Opus，**必须用 `-c:a copy` 纯换容器**：

  ```
  ffmpeg -hide_banner -loglevel error -i <in> -c:a copy -f webm <out>
  ```

- **严禁重编码。** 不要用 `libmp3lame`、`libopus` 或任何编码器参数。学习者的发音本就不标准，再叠一层有损压缩会直接伤害 §6.4 的 Error Preservation Rate——这是本产品的核心指标，不是可以为了省事牺牲的东西。
- `transcoded` 字段用于自证：任何情况下都应为 `false`。若将来出现必须重编码的输入，应显式抛错而不是静默降级。
- 目标格式**不得硬编码**，必须由调用方传入的 `supportedInputFormats` 决定（§6.2 的格式协商）。将来换 STT 供应商时这里应自动跟随。

## 3. `src/speech/tempFiles.ts` —— 临时文件生命周期（§8.3）

```
/tmp/japanese-agent/<turn-id>/input.oga
/tmp/japanese-agent/<turn-id>/input.webm
/tmp/japanese-agent/<turn-id>/reply.mp3
```

- turn 目录名用 `crypto.randomUUID()` 或等强度随机，**不可猜测**。
- 目录权限 `0o700`，文件权限 `0o600`。
- 导出 `createTurnWorkspace(): Promise<Workspace>`，`Workspace` 提供 `path(name)` 与 `dispose()`。
- `dispose()` 必须幂等，且**在成功与失败路径上都要被调用**（建议提供 `withTurnWorkspace(fn)` 包装器，用 `try/finally` 保证）。
- 导出 `cleanupStaleWorkspaces(maxAgeMs)`，供进程启动时清理上次崩溃的遗留目录（§8.3 要求"进程启动时"也清理）。
- 基目录可配置，测试时指向临时目录，不要污染真实 `/tmp/japanese-agent`。

## 4. Provider 契约与 mock

按 `docs/architecture.md` §6.2 定义接口。**关键是 §6.2 新增的格式协商字段**：

```ts
export interface SpeechToTextProvider {
  readonly name: string;
  readonly model: string;
  readonly supportedInputFormats: readonly string[];
  transcribe(audio: { path: string; container: string }, options?: SttOptions): Promise<Transcript>;
}

export interface Transcript {
  rawText: string;
  language?: string;
  durationMs?: number;
  confidence?: number;
  segments?: TranscriptSegment[];
  provider: string;
  model: string;
  usage: SttUsage;          // 至少含 audioSeconds
}

export interface TextToSpeechProvider {
  readonly name: string;
  readonly model: string;
  readonly outputFormat: string;      // mock 用 'mp3'
  synthesize(text: string, voice: VoiceConfig): Promise<AudioResult>;
}
```

**mock 实现要求：**

- `MockSttProvider` 的 `supportedInputFormats` 设为 `['mp3','mp4','mpeg','mpga','m4a','wav','webm']`，**刻意不含 `ogg`**，以复现真实约束、让 normalizer 的必要性在测试中可见。
- mock 转写结果可由构造参数注入，**默认返回带语法错误的原始文本**（如 `映画を見るました`）。这是刻意的：mock 绝不能"顺手改对"，否则测试会掩盖 §6.1 关心的失真问题。
- `MockTtsProvider.outputFormat` 为 `'mp3'`（对应 MiniMax），生成一个占位文件即可，不需要真实音频。
- mock 需支持模拟失败与超时，供后续容错测试使用。

## 5. 测试

- **ffmpeg 相关测试**：用 `isFfmpegAvailable()` 做守卫，缺 ffmpeg 时整组跳过（沿用 `tests/telegram/integration.test.ts` 的 `HAS_DB` 模式）。本机当前**没有安装 ffmpeg**，所以你大概率会看到跳过——**这是预期的，不要为了让测试"跑起来"而伪造或改用重编码**。
- 不依赖 ffmpeg 的部分必须有真实测试：
  - 输入容器已受支持时 normalizer **不调用 ffmpeg**（用 spy 断言）
  - 输入为 ogg 且不受支持时，构造出的 ffmpeg 参数**包含 `-c:a copy`、不含任何编码器参数**（这条即使没装 ffmpeg 也能测，断言参数数组即可，务必覆盖）
  - 临时目录权限为 0700、文件 0600
  - `dispose()` 幂等；`withTurnWorkspace` 在回调抛错时仍清理
  - `cleanupStaleWorkspaces` 只删超龄目录，不误删新目录
  - mock STT 不改写输入文本
  - 目标格式随 `supportedInputFormats` 变化而变化（换一组格式，行为随之改变）
