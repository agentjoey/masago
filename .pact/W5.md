## 1. Turn 状态机 `src/sessions/turnStateMachine.ts`

按 `docs/architecture.md` §8.2：

```
RECEIVED → AUDIO_READY → AUDIO_NORMALIZED → STT_DONE → LLM_DONE → PERSISTED
         → TEXT_SENT → VOICE_SENT → COMPLETED
```

**设计要求：**

- 状态转移是**纯函数**：`nextStatus(current) → status | null`、`isTerminal(status)`、`canTransition(from, to)`。纯函数便于穷举测试，不要把 IO 混进来。
- 非法转移必须抛出可识别错误，不得静默跳过。**尤其禁止状态倒退**（如 `COMPLETED → STT_DONE`）。
- `FAILED` 可从任意非终态进入，并记录失败发生在哪个状态。

## 2. Turn Runner `src/sessions/turnRunner.ts`

驱动状态机、每步之后持久化的执行器。这是 §8.2「重试从最后成功状态继续」的落地点。

**核心要求：**

- 每个步骤定义为 `{ status, execute(ctx) }`，执行成功后**立即持久化结果与新状态**，再进入下一步。
- 重启或重试时，从数据库读取 turn 当前状态，**跳过已完成的步骤**，从下一个未完成步骤继续。
- **关键行为（必须有测试）：** TTS 发送失败后重试，**复用已持久化的日文回复，绝不重新调用 LLM**。这是 §8.2 明写的要求，也是成本与一致性的关键。
- 每步保存 provider request ID（若有），供审计与排障。
- 步骤执行必须可注入（依赖注入或参数传入），以便测试用 mock 替换。

**幂等：** 同一 turn 重复驱动不得产生重复的外部调用或重复的 learning events。

缓存计价（Anthropic）：
- cache read ≈ 0.1 × input 单价
- cache write ≈ 1.25 × input 单价（5 分钟 TTL）

### 3.2 `pricing.ts` —— 计价逻辑

```ts
export function priceFor(provider: string, model: string, at: Date): PriceEntry | undefined;
export function estimateCost(usage: UsageInput, at: Date): { amountUsd: number; pricingVersion: string };
```

- **按调用时点 `at` 选择价目条目**，不是按当前时间。
- 找不到匹配价目时**不得静默返回 0**：返回明确的 "unknown pricing" 标记并记 warn 日志，成本字段置空而非零。零和未知是两回事，混淆会让 `/cost` 报出假的低成本。
- 金额用整数最小单位（微美元）内部计算，避免浮点累积误差；对外展示时再转换。

### 3.3 `recorder.ts` —— 写入 usage record

字段按 §12.3 齐全：

```
provider, model, operation
input_tokens, output_tokens, cached_input_tokens
audio_input_seconds, audio_output_seconds
tts_characters
provider_reported_units
estimated_cost, currency, pricing_version
latency_ms, success, error_code
```

- **失败的调用也要记录**（`success=false` + `error_code`），否则成本与失败率都会失真。
- 记录写入不得阻塞主链路：失败时记 error 日志，不让计量问题拖垮学习功能。

### 3.4 `aggregate.ts` —— `/cost` 聚合

按日 / 周 / 月 × provider / model / operation 聚合。时区用 `config.userTimezone` 计算"今日"边界，**不要用 UTC 日界**——用户在 Asia/Singapore，UTC 日界会让"今天的花费"在下午 8 点突然归零。

## 4. 测试

**状态机：**
- 穷举所有合法转移路径通过
- 非法转移（跳步、倒退、终态再转移）均抛错
- `FAILED` 可从各非终态进入并记录来源状态

**Runner（最重要的一组）：**
- 从 `RECEIVED` 完整跑到 `COMPLETED`，各步骤按序执行且各持久化一次
- **在 `TEXT_SENT` 后模拟 TTS 失败并重试：断言 LLM 步骤的 mock 被调用次数仍为 1**（即复用已持久化回复，未重新调用）
- 从中间状态恢复：只执行剩余步骤，已完成步骤的 mock 调用次数为 0
- 同一 turn 重复驱动不产生重复外部调用

**计价（重点验证版本化）：**
- `claude-sonnet-5` 在 **2026-08-20** 的调用按 $2/$10 计价
- 同一模型在 **2026-09-15** 的调用按 $3/$15 计价
- **同一条历史记录在价目表新增条目后重算，金额不变**（这是"不用最新价回写"的核心断言）
- 未知 provider/model 返回 unknown 而非 0
- MiniMax 字符计价与 OpenAI 分钟计价各自正确
- 缓存读/写单价按 0.1× / 1.25× 计算

**聚合：**
- 跨 UTC 日界但在用户时区同一天的两条记录，被聚合进同一天
- 失败调用计入调用次数但成本处理正确
