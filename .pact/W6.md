## 1. Telegram 语音下载 `src/telegram/voice.ts`

```ts
export interface VoiceDownloader {
  download(fileId: string, destPath: string): Promise<{ bytes: number; container: string }>;
}
```

- 用 grammY 的 `getFile` 拿 `file_path`，再从 Telegram 文件端点下载到指定路径。
- **下载前校验**（§8.1 第 4 步）：mime type、大小 ≤ `config.audio.maxSizeMb`、时长 ≤ `config.audio.maxDurationSeconds`。任一不合格立即拒绝并返回可识别错误类型，**不进入后续步骤**。
- 容器类型从 Telegram 的 `mime_type`（通常 `audio/ogg`）推导，不要靠文件扩展名猜。
- **Bot token 绝不出现在日志或错误信息里**——文件下载 URL 里含 token，这是最容易泄漏的一处。构造 URL 时注意不要把它塞进 error message。
- 必须可注入/可打桩，测试不得真的联网。

## 2. Voice Turn Pipeline `src/sessions/voiceTurn.ts`

把 §8.1 的链路实现为 W5 `runTurn` 所需的 `TurnStep[]`：

| 状态 | 步骤职责 |
|---|---|
| `AUDIO_READY` | 创建 turn workspace（W4 `withTurnWorkspace`）、下载语音、校验 |
| `AUDIO_NORMALIZED` | 调 W4 `normalizeForStt`，目标格式取自 STT provider 的 `supportedInputFormats` |
| `STT_DONE` | 调 STT provider → **raw transcript**；单独产出 normalized transcript，**不得覆盖 raw**（§6.3）；记录 usage |
| `LLM_DONE` | 调注入的 tutor（本任务给最小实现即可，真正的 Tutor 行为属于阶段 3）；记录 usage |
| `PERSISTED` | 在**单个数据库事务**中写入 turn 输出与状态 |
| `TEXT_SENT` | 发送日文文本回复 |
| `VOICE_SENT` | 调 TTS provider 合成并作为 Telegram 语音条发送；记录 usage |
| `COMPLETED` | 清理临时文件、标记完成 |

**硬性要求：**

- **所有 provider 与 Telegram 发送能力经依赖注入传入**，`voiceTurn.ts` 内不得直接 import 任何具体 provider 实现或 SDK。
- `raw_transcript` 与 `normalized_transcript` 分两列写入，raw 永不被标准化结果覆盖。这是 Error Bank 不失真的前提（§6.3）。
- TTS 输出为 mp3，**直接经 `sendVoice` 发送，不做任何转码**（§4.1 已核实 Telegram 接受 mp3）。
- 临时文件在成功、失败两条路径上都必须清理——用 W4 的 `withTurnWorkspace` 包裹整条管线，别手写 try/finally。
- 每次 provider 调用都产生 usage record（含失败调用），经 W5 的 `recordUsage` 回调。

## 3. 降级行为（§9.1）

按降级矩阵实现，且必须有对应测试：

| 故障 | 要求行为 |
|---|---|
| remux 失败 | 提示重新发送或改用文字；**不进入 STT** |
| STT 失败 | 提示重发或改文字；**不生成任何错误评价、不写 learning events** |
| LLM 失败 | 简短说明本轮无法完成；**不制造伪造学习事件** |
| TTS 失败 | **仍然发送日文文字**，turn 不算完全失败；voice 状态标记为失败 |

**TTS 失败这条最重要**：用户必须拿到文字回复。语音是增强，不是前提。

## 5. 测试

- 完整语音 turn 用 mock provider 跑通：下载 → remux → STT → tutor → 持久化 → 文字 → 语音 → COMPLETED
- **`raw_transcript` 保留了 mock STT 返回的语法错误原文**，与 `normalized_transcript` 不同
- 四条降级路径各一条测试，断言其"不做什么"（不调 STT、不写 learning events、仍发文字）
- TTS 失败后重试：**LLM mock 调用次数为 0**（复用 W5 的保证，此处验证接线没破坏它）
- 超大 / 超时长 / 错误 mime 的语音被拒且不触发任何 provider 调用
- 临时文件在成功与失败路径上均被清理（断言目录不存在）
- **Bot token 不出现在任何日志输出中**（用内存 logger 捕获后断言）
- W3 的文本 echo 与鉴权/幂等测试仍全部通过
