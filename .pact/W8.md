## 1. 已核实的 Anthropic API 契约（2026-08-12）

**照此实现。以下每一条都是照旧习惯写会直接 400 或行为错误的地方。**

```ts
import Anthropic from '@anthropic-ai/sdk';
const client = new Anthropic({ apiKey: config.llm.apiKey });

const response = await client.messages.create({
  model: 'claude-sonnet-5',        // 精确字符串，不要加日期后缀
  max_tokens: 16000,               // 非流式建议值
  system: [
    { type: 'text', text: TUTOR_POLICY, cache_control: { type: 'ephemeral' } },
  ],
  messages: [...],
  output_config: { format: { type: 'json_schema', schema: TUTOR_SCHEMA } },
});
```

| 必须遵守 | 说明 |
|---|---|
| **不要传 `temperature` / `top_p` / `top_k`** | Sonnet 5 上传非默认值直接 **400**。要控制风格用 prompt，不要用采样参数。 |
| **不要用 assistant prefill** | 最后一轮 assistant 预填在 Sonnet 5 上 **400**。要约束输出格式用 `output_config.format`。 |
| **用 `output_config.format`，不要用 `output_format`** | 后者已废弃。 |
| **不要传 `thinking: {type:'enabled', budget_tokens:N}`** | 已移除，**400**。Sonnet 5 省略 `thinking` 即为 adaptive。 |
| **`response.content` 是可判别联合** | 必须按 `block.type === 'text'` 收窄后再取 `.text`，直接 `content[0].text` 过不了 typecheck。 |
| **prompt caching 最小前缀 1024 tokens** | Sonnet 5 的门槛。低于此静默不缓存（`cache_creation_input_tokens: 0`），不报错。 |

**缓存放置（§6.7 把 prompt caching 列为成本优化第一项）：** Tutor Policy 与 Learner Profile 是稳定前缀，放最前面并打 `cache_control`；最近 turns、当前消息等易变内容放其后。**system 里绝不能插入时间戳或每次变化的值**——前缀变一个字节，整个缓存作废。

**usage 字段映射到 §12.3：**

```
response.usage.input_tokens                → inputTokens
response.usage.output_tokens               → outputTokens
response.usage.cache_read_input_tokens     → cachedInputTokens
response.usage.cache_creation_input_tokens →（计入成本，缓存写为 1.25×）
```

`cachedInputTokens` 是验证缓存是否真的生效的唯一手段（§12.2 要求可观测）。若连续多轮该值恒为 0，说明前缀被什么东西打破了。

## 2. 最小 Tutor `src/agent/tutor.ts`

实现 W6 已定义的 `Tutor` 接口（**不要改那个接口**，改了说明解耦有问题）。

**本任务只做"最小"：** 接住用户日语、给出自然的日语回复。**不实现**三种模式、纠错卡、Correction Scheduler、Retry——那些是阶段 3。

但输出 schema **现在就要结构化**，让阶段 3 是扩展而非重写。最小 schema：

```json
{
  "reply": { "japanese": "...", "translation": null },
  "detectedIssues": [],
  "session": { "continue": true }
}
```

`detectedIssues` 本任务允许模型填但**不做任何呈现**——按 §5.4，识别与呈现是分开的，呈现时机归 Correction Scheduler 管（阶段 3）。**现在就把这条结构立住，不要图省事直接把纠正塞进 reply 文本里**，否则阶段 3 要推倒重来。

用 Zod 定义 schema 并校验响应（INTERFACES §0）。校验失败按 §9.1 做一次 repair/retry，仍失败则降级。
